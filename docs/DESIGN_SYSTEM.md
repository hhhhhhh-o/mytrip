# MYTrip 视觉与交互规范

## 1. 视觉方向

整体克制、清晰，接近 iOS 原生应用；规则可根据真实的信息层级和交互需要调整，但每次偏离必须有明确理由。

## 2. 固定原则

- 大面积留白；
- 使用系统字体；
- 主标题明显，辅助文字降低视觉权重；
- 页面只保留一个主要强调色；
- 不使用渐变背景；
- 不使用发光效果；
- 不使用玻璃拟态；
- 不堆叠多层卡片；
- 普通卡片不依赖阴影区分层级；
- 固定、候选、确认、锁定和冲突状态必须容易识别；
- 同类组件保持一致。

## 3. 可调整部分

- 字号、间距和圆角具体数值；
- 是否使用细边框或极轻阴影；
- 特殊页面的布局；
- 语义颜色；
- Web 与原生端的图标实现。

## 4. 基础颜色

```text
主要强调色  #007AFF
主文字      #1C1C1E
次级文字    #8E8E93
分割线      #D1D1D6
页面背景    #F2F2F7
内容背景    #FFFFFF
错误/冲突   #FF3B30
提醒        #FF9500（少量使用）
```

红色和橙色仅承担错误、冲突或临近提醒等语义，不作为普通装饰。

## 5. 字体

```css
font-family:
  -apple-system,
  BlinkMacSystemFont,
  "SF Pro Text",
  "PingFang SC",
  sans-serif;
```

建议层级：

- 页面大标题：32–34px；
- 分区标题：20–22px；
- 正文与列表标题：16–17px；
- 辅助文字：13–15px；
- 标签：12–13px。

## 6. 圆角和容器

- 输入框与普通按钮：8–10px；
- 内容容器：10–12px；
- 底部 Sheet 顶部：14–16px；
- 不将所有控件做成胶囊形；
- 优先使用留白和分割线，而不是为每条行程增加独立卡片。

## 7. 图标

原生 iOS 优先使用 SF Symbols。Web/PWA 使用视觉一致的线性图标替代，不混用不同线宽和风格。

推荐语义：

- 航班：`airplane`；
- 车次：`tram.fill`；
- 酒店：`bed.double.fill`；
- 活动：`ticket.fill`；
- 地点：`mappin`；
- 日期：`calendar`；
- 锁定：`lock.fill`；
- AI 建议：`wand.and.stars`；
- 提醒：`bell`；
- 添加：`plus`。

## 8. 行程时间线

- 时间位于固定宽度的左列；
- 内容位于右侧，使用细分割线区分；
- 已锁定项目使用强调色锁图标和简短文字，不使用大面积高饱和背景；
- 候选项目降低视觉权重；
- 冲突项目使用红色图标和说明；
- 同一天不为每一项套多层卡片。

## 9. 操作层级

- 每个页面只有一个主要蓝色操作；
- 次要操作使用文字按钮、列表入口或菜单；
- 删除使用红色，并在最终执行前确认；
- 编辑、移动、锁定和删除可收纳在 `···` 菜单或底部 Sheet；
- AI 生成结果先预览，再由用户确认加入正式行程。

## 10. 无障碍与可用性

- 正文和背景保持足够对比度；
- 交互区域满足移动端点击尺寸；
- 状态不能只依赖颜色表达；
- 支持系统字体缩放；
- 动效服务于状态变化，不作为装饰；
- 减少动态效果开启时仍可完整使用。
