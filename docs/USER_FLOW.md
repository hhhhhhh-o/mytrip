# MYTrip 通用用户流程

## 1. 首次使用

```text
打开 MYTrip
→ 查看隐私和 AI 识别说明
→ 创建第一段旅行
→ 输入目的地与日期
→ 进入旅行主页
```

## 2. 导入固定安排

```text
点击“导入行程”
→ 选择截图、链接、文字或手动添加
→ AI 分类并提取字段
→ 用户逐项检查
→ 修正错误或补充缺失字段
→ 确认并加入时间线
→ 根据需要锁定
```

适用内容包括航班、车次、酒店、演唱会、体育赛事、餐厅预约、商务会议、租车取还和任何有确定时间的活动。

## 3. 添加灵活活动

```text
添加兴趣与旅行偏好
→ 导入攻略或获取系统候选地点
→ 查看地点来源与推荐原因
→ 标记“必须去 / 有空再去 / 不感兴趣”
→ AI 生成可编辑的行程初稿
```

## 4. 修改与锁定

```text
打开某个行程项
→ 修改日期、时间、地点或停留时长
→ 保存
→ 选择“确认”或“锁定”
→ AI 只重新编排未锁定且受影响的部分
```

如果修改内容与原始票据不一致，系统提示差异，但允许用户继续。

## 5. 冲突处理

```text
发现时间重叠或交通时间不足
→ 标记冲突位置
→ 给出原因和可选处理方案
→ 用户选择解锁、移动、缩短或保留
```

系统不能自动移动已锁定项目。

## 6. 旅行执行

```text
显示距出发天数
→ 临近事件时提供提醒
→ 展示下一项行程和建议出发时间
→ 用户标记完成或跳过
→ 必要时重新编排后续未锁定活动
```

## 7. 页面结构

### 旅行列表

- 即将出发；
- 进行中；
- 已结束；
- 新建旅行。

### 旅行主页

- 旅行名称、日期和倒计时；
- 导入入口；
- 每日时间线；
- 待确认信息；
- 冲突提示。

### 导入收件箱

- 等待识别；
- 等待用户确认；
- 已加入行程；
- 识别失败。

### 行程详情

- 当前字段；
- 来源和原始证据；
- 修改记录；
- 确认、锁定、解锁和删除操作。

### 候选地点

- 用户导入；
- 系统推荐；
- 必须去；
- 有空再去；
- 不感兴趣。

## 8. 示例场景的使用方式

“首尔演唱会旅行”“东京美食旅行”或“上海商务出差”等案例只用于验证同一套通用流程。产品代码和数据模型不得写死特定城市、国家、活动类型或平台名称。
